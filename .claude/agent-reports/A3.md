## What I built
- **Use cases** (`domain/usecases/`): `UpdatePrice`, `PreviewBulkPrices`, `ApplyBulkPrices`,
  `GetProductPricing`, `GetPriceHistory`. Every write checks `Permission.editPrices` first.
- **Domain services** (`domain/services/`): `PriceCalculator` (the one place percent / fixed /
  rounding / clamping math lives, shared by preview and apply so they can't drift),
  `validateBulkRule`, `PriceBatchResult` (count, average change, up/down).
- **Data**: `PricingLocalDataSource` (all pricing SQL), `PricingRepositoryImpl`, row models and the
  `price_changes` mapper.
- **Screens/routes**:
  - `/prices/:productId` — single price sheet: new price, optional new cost, live margin
    `(price − cost) / price`, below-cost and zero warnings, save.
  - `/prices/bulk` — three-phase flow in one screen: **form** (scope = category + sub-categories,
    or a chosen set of products · percent or fixed · increase/decrease · price/cost/both ·
    rounding none/0.05/0.25/0.50/1.00 × nearest/up) → **preview** (old → new, margin, below-cost
    and zero flags, count and warning summary) → **summary** (n changed, average change, up/down,
    "view changes" list). `?ids=a,b` preselects products.
- **Tables written**: `products.price_minor`, `products.cost_minor` (plus their `updated_at`, see
  change requests) and `price_changes` — nothing else.
- **Event**: `bulk_price_updated` `{count, durationMs, mode}`; `durationMs` is measured by the
  screen from open to confirm (the business-plan §9 repricing metric).
- **l10n**: 60 `pricing_*` keys in en + ar; all layout uses `EdgeInsetsDirectional`/`start`/`end`
  or direction-neutral widgets.

## Tests
Unit: 32 (calculator 16, use cases 16) · Repository: 17 · Widget: 19 · All green: **yes** (68).

Highlights against the acceptance list:
- **Rounding & percent math incl. edge cases** — 0 price, negative result blocked at zero, every
  rounding step lands on a multiple of itself, nearest vs. up, cost never rounded.
- **Staff calling a use case directly** → `PermissionFailure`, and the repository is never called
  (also asserted for a *locked* owner session).
- **`price_changes` rows share a `batch_id`**, carry the acting `profile_id`, and record the cost
  only when it changed.
- **Atomicity**: a repository test forces a primary-key clash on the 3rd write of a batch and
  asserts every product still has its old price and no history row was added.
- **Performance**: 200 products in one category — preview and apply are asserted under the
  brief's 1 s / 2 s budgets (both run in a few ms on an in-memory DB; a device run is still worth
  doing at G1).

## Decisions I made (brief was ambiguous)
- **Rounding applies to the price only.** A cost is what the shop paid; rounding it to 0.25 would
  corrupt margins. The rounding controls are hidden when the target is *cost only*.
- **A negative result is clamped to zero, not refused.** "Negative result blocked" is enforced as
  "a price can never be written below zero"; the preview flags those rows as *Zero* and
  *Below cost* so the owner sees them before confirming. Refusing the whole batch would punish a
  legitimate 200-product update because of one cheap item.
- **The batch summary is a phase of `/prices/bulk`, not a new route** — `RoutePaths` is frozen and
  needs no new constant for it. (Change request below if a deep link is wanted later.)
- **The single-price screen is a full page, not a modal sheet.** It has to work when the URL is
  typed on web, and it is reached by `context.go`, so a route-backed page is the honest shape.
- **No event for a single price edit.** `AppEvent` has no `price_updated`, and logging
  `bulk_price_updated` with count 1 would pollute the pilot metric.
- **`GetProductPricing` reuses `previewBulk` with a 0 % rule** instead of adding a method to the
  frozen repository interface — it returns exactly the name/price/cost the screen needs.
- **Pricing reads `products` and `categories` directly** (read-only) rather than depending on A2's
  repository providers, so the two features never block each other. Ownership is unchanged: only
  `price_minor`, `cost_minor` and `price_changes` are written.
- **No `FeatureFlag` check** — prices are core in every tier (brief; `feature_flag.dart` has no
  pricing flag). `FeatureFlag.priceHistory` gates the *history screen*, which is D2, so I
  implemented `history()` in the repository but built no UI for it.
- **`applyBulk` returns `ValidationFailure(products, no_changes)`** when the rule would change
  nothing, rather than an empty batch id.
